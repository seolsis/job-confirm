# AI 채용공고 분석 서비스 — 제품 기획서 (PRD)

> **한 줄 정의**: 채용공고 URL을 붙여넣으면 AI가 공고를 분석하고, 내 프로필과 비교해 적합도를 알려주는 서비스.
>
> **핵심 가치**: "이 공고, 나한테 맞아?"라는 질문에 30초 안에 근거 있는 답을 준다.
> 취준탭(공고 관리 보드)은 분석 결과를 축적·관리하기 위한 **부가 기능**이다.

- 문서 버전: v1.0 (2026-07-08)
- 작성 관점: PM (Product Manager)
- 상태: 기획 단계 — 코드 작성 전

## 1. 서비스 전체 구조

### 1.1 제품 포지셔닝

| 구분 | 내용 |
|---|---|
| 타깃 사용자 | 신입~주니어 취업준비생 (1차), 이직 준비 중인 재직자 (2차) |
| 핵심 문제 | 공고를 읽어도 "내가 지원해도 되는 수준인지" 판단이 어렵고, 여러 공고를 비교·관리할 도구가 없다 |
| 핵심 해법 | URL 입력 → AI 공고 구조화 분석 → 내 프로필 대비 적합도 산출 → 결과를 취준탭에 저장·관리 |
| 차별점 | 단순 공고 스크랩/일정 관리가 아니라 **"나 기준의 분석"**이 붙은 공고 관리 |

```

└──────────────────────────┬──────────────────────────────────┘
                           │ REST / WebSocket(분석 진행 상태)
┌──────────────────────────┴──────────────────────────────────┐
│                        API 서버 (Backend)                    │

└───────┬──────────────────┬──────────────────┬───────────────┘
        │                  │                  │
┌───────┴───────┐  ┌───────┴────────┐  ┌──────┴────────┐

│ · 사이트별 어댑터│  │ · 프로필 매칭    │  │   분석 결과     │
```

### 1.3 핵심 도메인 모델 (개념 수준)

| 엔티티 | 설명 | 주요 속성 |
|---|---|---|
| User | 서비스 사용자 | 이메일, 인증 정보, 알림 설정 |
| Profile | 사용자의 이력 정보 (분석의 비교 기준) | 학력, 경력, 스킬, 자격증, 프로젝트, 어학, 희망 직무/연봉/지역 |
| JobPosting | 수집된 공고 원본 + 구조화 데이터 | 원본 URL, 원문 스냅샷, 회사, 직무, 자격요건, 우대사항, 마감일, 근무지, 고용형태 |
| Analysis | 프로필 × 공고 분석 결과 | 적합도 점수, 항목별 매칭 상세, 강점/보완점, 생성 시각, 사용 모델 버전 |
| Application | 취준탭의 한 카드 (공고에 대한 나의 진행 상태) | 상태(관심~불합격), 상태 변경 이력, 메모, 지원 마감일, 일정 |

> **설계 포인트**: `JobPosting`(공고 자체)과 `Application`(나의 진행 상태)을 분리한다.
> 같은 공고를 여러 사용자가 분석해도 원문 수집·구조화는 1회만 하고 캐시를 재사용할 수 있고,
> 분석(`Analysis`)은 "프로필 스냅샷 × 공고" 단위로 남겨서 프로필이 바뀌면 재분석이 가능하다.

### 1.4 AI 분석 파이프라인 (핵심 기능의 내부 단계)

1. **수집(Fetch)**: URL 접근 → HTML/렌더링 결과 확보. 주요 채용 사이트(사람인, 원티드, 잡코리아, 링크드인, 자사 채용페이지 등)별 어댑터 + 범용 본문 추출기.
2. **정제(Clean)**: 광고/내비게이션 제거, 본문·이미지 내 텍스트(OCR은 확장 단계) 추출, 원문 스냅샷 저장(공고 삭제 대비).
3. **구조화(Extract)**: LLM으로 공고를 표준 스키마로 변환 — 회사, 직무명, 주요 업무, 자격요건(필수), 우대사항, 기술스택, 경력 요건, 학력 요건, 근무 조건, 마감일, 채용 절차.
4. **매칭(Match)**: 프로필의 각 항목을 공고 요건과 대조. 필수요건 충족 여부 / 우대사항 보유 여부 / 스킬 갭을 판정.
5. **산출(Score & Report)**: 종합 적합도(0~100) + 항목별 점수 + 자연어 리포트(강점, 보완점, 지원 전 준비 제안) 생성.
6. **저장(Persist)**: 분석 결과를 저장하고, 사용자가 원클릭으로 취준탭 카드(`관심 공고`)로 등록.

> **비기능 요구**: 분석은 비동기 처리(수 초~수십 초 소요). 진행 단계를 실시간으로 노출("공고 수집 중 → 분석 중 → 프로필 비교 중")해 이탈을 막는다. 동일 URL 재분석 요청은 공고 스냅샷 캐시를 재사용해 비용을 절감한다.

## 2. 사용자 플로우

### 2.1 최초 방문 → 온보딩 플로우

```
랜딩 페이지
   │  "공고 URL을 붙여넣어 보세요" (비로그인 체험 허용 — 아래 2.5 참고)
   ▼
회원가입 / 로그인 (이메일, 소셜 로그인)
   ▼
프로필 온보딩 (단계별 위저드)
   ① 희망 직무·직군 선택
   ② 학력 / 경력 입력
   ③ 스킬·자격증·어학 입력 (자동완성 태그)
   ④ (선택) 이력서 파일 업로드 → AI가 프로필 자동 채움
   ▼
"첫 공고를 분석해 보세요" → 메인(공고 입력) 화면
```

> **온보딩 원칙**: 프로필 입력은 분석 품질의 전제 조건이지만 진입 장벽이기도 하다.
> ①~② 최소 입력만으로 첫 분석을 허용하고, 결과 화면에서 "프로필을 더 채우면 분석이 정확해져요"로 보완을 유도한다(Progressive Profiling).

### 2.2 핵심 플로우 — 공고 분석 (메인 기능)

```
메인 화면에서 공고 URL 입력 → [분석하기]
   ▼
수집 단계 (진행 상태 표시)
   ├─ 성공 → 공고 미리보기 카드 표시 ("이 공고가 맞나요?")
   └─ 실패 → 폴백: "공고 본문을 직접 붙여넣어 주세요" (텍스트 입력)
   ▼
AI 분석 진행 (단계 표시: 공고 정리 → 요건 추출 → 프로필 비교)
   ▼
분석 결과 화면
   ├─ 종합 적합도 점수 + 한 줄 결론 ("필수요건 5개 중 4개 충족")
   ├─ 항목별 매칭 상세 (충족 ✅ / 부분 충족 ⚠️ / 미충족 ❌ / 판단 불가 ❔)
   ├─ 강점 요약 / 보완점 & 준비 제안
   └─ 공고 구조화 요약 (업무, 요건, 우대, 마감일, 절차)
   ▼
[취준탭에 저장] → 상태 '관심 공고'로 카드 생성
```

### 2.3 부가 플로우 — 취준탭 (공고 관리)

```
취준탭 진입 (칸반 보드)
   │
   ├─ 카드 조회: 회사명, 직무, 적합도 점수 뱃지, 마감 D-day
   ├─ 상태 변경: 드래그&드롭 또는 카드 내 상태 선택
   │     관심 공고 → 지원 예정 → 지원 완료 → 서류 합격 → 필기 합격
   │        → 면접 예정 → 최종 합격 / (어느 단계에서든) 불합격
   ├─ 카드 상세: 분석 결과 다시 보기, 메모 작성, 일정(마감일·면접일) 입력
   └─ 필터/정렬: 상태별, 마감 임박순, 적합도순, 회사명 검색
```

> **상태 전이 정책**: 순방향 진행이 기본이지만 강제하지 않는다(자유 이동 허용).
> 다만 `불합격` 이동 시 탈락 단계(서류/필기/면접)를 함께 기록해 추후 통계(전환율)의 재료로 쓴다.
> 모든 상태 변경은 이력(누가·언제·무엇→무엇)으로 남긴다.

### 2.4 재분석 플로우

```
프로필 수정 완료
   ▼
"프로필이 변경되었습니다. N개의 저장된 공고를 다시 분석할까요?"
   ▼
선택한 공고 일괄 재분석 → 점수 변화 표시 (72 → 81 ▲9)
```

### 2.5 비로그인 체험 플로우 (전환 퍼널)

```
랜딩에서 URL 입력 (로그인 없이)
   ▼
공고 구조화 분석까지만 무료 노출 (요건/우대/마감 정리)
   ▼
"내 프로필과의 적합도를 보려면 가입하세요" → 회원가입 전환
```

## 3. 필요한 화면

### 3.1 화면 목록 총괄

| # | 화면 | 목적 | 우선순위 |
|---|---|---|---|
| S1 | 랜딩 페이지 | 가치 제안 + 비로그인 체험 입구 | MVP |
| S2 | 회원가입 / 로그인 | 계정 생성 (이메일 + 소셜) | MVP |
| S3 | 프로필 온보딩 위저드 | 분석 기준이 되는 프로필 최초 입력 | MVP |
| S4 | 메인 — 공고 입력 | URL 입력, 최근 분석 목록 | MVP |
| S5 | 분석 진행 화면 | 비동기 분석 진행 상태 표시 | MVP |
| S6 | 분석 결과 화면 | 적합도 + 매칭 상세 + 공고 요약 | MVP |
| S7 | 취준탭 — 칸반 보드 | 상태별 공고 카드 관리 | MVP |
| S8 | 공고 카드 상세 | 분석 결과 재확인, 메모, 일정 | MVP |
| S9 | 프로필 관리 | 프로필 조회·수정, 이력서 업로드 | MVP |
| S10 | 설정 / 마이페이지 | 계정, 알림, 데이터 관리 | MVP(최소) |
| S11 | 대시보드(취준 현황 통계) | 지원 현황·전환율 시각화 | 확장 |
| S12 | 공고 비교 화면 | 2~3개 공고 나란히 비교 | 확장 |
| S13 | 온보딩 튜토리얼/빈 상태 화면 | 첫 사용 가이드 | MVP(간이) |

### 3.2 주요 화면 상세

#### S4. 메인 — 공고 입력
- 중앙에 큰 URL 입력창 + [분석하기] 버튼 (제품의 얼굴, 검색엔진처럼 단순하게)
- URL 유효성 즉시 검증(형식/지원 사이트 안내)
- 하단: 최근 분석한 공고 리스트(점수 뱃지 포함), "붙여넣기로 분석" 폴백 진입점
- 남은 분석 횟수 표시(무료 플랜 쿼터)

#### S6. 분석 결과 화면 (제품의 핵심 화면)
- **상단(결론 먼저)**: 종합 적합도 점수(0~100) + 등급 라벨(적극 추천/도전 가능/준비 필요) + 한 줄 결론
- **매칭 상세 테이블**: 공고 요건 항목별로 `요건 내용 | 내 프로필 근거 | 판정(✅⚠️❌❔)`
  - ❔(판단 불가)는 "프로필에 관련 정보가 없어요 → 추가하기" 링크로 프로필 보완 유도
- **강점 / 보완점 카드**: 자소서·면접에서 어필할 강점, 지원 전 준비하면 좋을 것
- **공고 요약 섹션**: 주요 업무, 필수/우대, 채용 절차, 마감일, 근무 조건 (원문 링크 + 스냅샷 보기)
- **하단 CTA**: [취준탭에 저장] (저장 시 상태 선택 가능, 기본 '관심 공고')
- **신뢰 장치**: "AI 분석은 참고용이며, 최종 판단은 원문 확인 후 하세요" 고지 + 분석 근거(어떤 문장에서 추출했는지) 펼쳐보기

#### S7. 취준탭 — 칸반 보드
- 컬럼: 관심 공고 / 지원 예정 / 지원 완료 / 서류 합격 / 필기 합격 / 면접 예정 / 최종 합격 / 불합격
  - 8개 컬럼은 한 화면에 많으므로: 데스크톱은 가로 스크롤 + 컬럼 접기, 모바일은 상태 탭 전환형 리스트로 대응
- 카드 구성: 회사 로고/명, 직무명, 적합도 점수 뱃지, 마감 D-day(임박 시 강조), 메모 존재 표시
- 인터랙션: 드래그&드롭 상태 변경, 카드 클릭 → 상세(S8)
- 상단 바: 필터(상태/마감/점수), 정렬, 검색, [+ 새 공고 분석] 버튼

#### S9. 프로필 관리
- 섹션형 편집: 기본 정보 / 학력 / 경력 / 스킬 / 자격증·어학 / 프로젝트 / 희망 조건
- 프로필 완성도 게이지(%) — 완성도가 분석 정확도와 직결됨을 명시
- 이력서 파일 업로드(PDF) → AI 파싱으로 자동 채움 → 사용자 확인·수정
- "프로필 변경 시 저장된 공고 재분석" 안내 배너

## 4. 필요한 기능

### 4.1 기능 총괄표

| 영역 | 기능 | 설명 | 우선순위 |

### 4.2 정책이 필요한 항목 (기능 뒤의 규칙)

- **적합도 점수 산식**: 필수요건 충족률(가중 높음) + 우대사항 보유율 + 경력/직무 정합성의 가중 합. 산식과 등급 구간(예: 80+ 적극 추천 / 60~79 도전 가능 / 60 미만 준비 필요)은 서비스 정책으로 문서화하고, LLM 출력의 일관성을 위해 점수 산출은 규칙 기반 + LLM 판정의 하이브리드로 설계한다.
- **분석 쿼터**: LLM 비용 통제를 위해 무료 사용자 일/월 분석 횟수 제한(예: 월 20회). 동일 URL 재조회는 쿼터 미차감(캐시).
- **데이터 보존**: 공고 스냅샷은 저작권·약관 이슈를 고려해 "본인 열람용 보관"으로 한정하고 외부 공유 기능에서는 원문 링크만 노출.
- **크롤링 컴플라이언스**: robots.txt·사이트 약관 준수, 요청 속도 제한, 차단 사이트는 붙여넣기 폴백으로 안내. (법무 검토 필요 — 7장 참고)

## 5. MVP 정의

### 5.1 MVP 목표와 검증 가설

> **가설**: "취준생은 공고를 저장·관리하는 도구보다, 공고가 나에게 맞는지 판단해 주는 도구에 더 큰 가치를 느낀다."

- **핵심 검증 지표 (North Star 후보)**: 주간 공고 분석 수 / 분석 → 취준탭 저장 전환율
- 보조 지표: 가입 → 첫 분석 완료율(활성화), 분석 결과 피드백 긍정률, 4주 리텐션

### 5.2 MVP 범위 (In)

| 영역 | 포함 내용 |
|---|---|
| 인증 | 이메일 + 구글 로그인 |
| 프로필 | 수동 입력 (희망 직무, 학력, 경력, 스킬, 자격증) — 이력서 파싱은 제외 |
| 수집 | 국내 주요 채용 사이트 2~3곳 어댑터(원티드·사람인 우선) + 범용 추출기 + **붙여넣기 폴백(필수)** |
| 분석 | 공고 구조화 + 프로필 매칭 + 적합도 점수 + 강점/보완점 리포트 + 진행 상태 표시 |
| 취준탭 | 8단계 칸반 보드, 드래그&드롭, 카드 메모, 마감 D-day |
| 운영 | 무료 쿼터(월 N회), 분석 결과 👍/👎 피드백, 기본 어드민(수집 실패 로그) |
| 화면 | S1~S10, S13 (3.1 표의 MVP 표기 항목) |

### 5.3 MVP 제외 (Out) — 의도적으로 미룸

- 이력서 파일 자동 파싱 (수동 입력으로 대체)
- 알림(이메일/푸시) — D-day 시각 강조로 1차 대체
- 대시보드 통계, 공고 비교, 자소서 도우미
- 모바일 앱 (반응형 웹으로 대응)
- 결제/유료 플랜 (쿼터 제한만 구현, 과금은 검증 후)

### 5.4 MVP 개발 순서 제안 (마일스톤)

1. **M1 — 분석 코어 (검증의 심장)**: URL 수집 + 붙여넣기 폴백 → 공고 구조화 → 프로필 매칭 → 결과 화면. *이 단계만으로 내부 테스트 가능해야 한다.*
2. **M2 — 계정과 프로필**: 인증, 프로필 온보딩, 분석 결과 저장.
3. **M3 — 취준탭**: 칸반 보드, 상태 관리, 메모, D-day.
4. **M4 — 런칭 준비**: 쿼터, 피드백 수집, 랜딩, 비로그인 체험, 어드민 최소 기능.

### 5.5 MVP 성공 기준 (런칭 후 4~6주 판단)

- 가입자의 60% 이상이 첫 분석을 완료 (활성화)
- 분석 1회 이상 사용자의 40% 이상이 취준탭에 공고 저장 (핵심 기능 → 부가 기능 연결 확인)
- 분석 결과 피드백 긍정률 70% 이상 (분석 품질)
- 수집 성공률 85% 이상 (폴백 제외 자동 수집 기준)

## 7. 부족한 기능 제안 (PM 관점 갭 분석)

원래 요구사항에는 없지만, 실제 서비스로 만들려면 반드시 짚어야 할 항목들.

### 7.1 제품 갭 — 사용자 경험에 뚫린 구멍

1. **수집 실패 폴백 (치명적)**: 링크드인 등 다수 채용 사이트는 로그인 장벽·봇 차단으로 크롤링이 자주 실패한다. "본문 붙여넣기" 폴백이 없으면 핵심 기능 자체가 먹통이 되는 경험을 준다. → **MVP 필수로 승격함** (5.2 반영).
2. **판단 불가(❔) 상태 설계**: 프로필에 정보가 없어 판정할 수 없는 요건을 "미충족"으로 처리하면 점수가 부당하게 깎이고 신뢰를 잃는다. 별도 상태로 두고 프로필 보완 유도 장치로 활용해야 한다.
3. **공고 마감/삭제 대응**: 저장해 둔 공고 링크가 죽는 일은 매우 흔하다. 원문 스냅샷 보관 + 카드에 "마감된 공고" 뱃지 자동 표시가 필요하다.
4. **중복 공고 처리**: 같은 공고를 다른 URL(사람인/원티드/자사 페이지)로 재분석하는 경우 감지·병합 제안. 쿼터 낭비와 보드 중복을 막는다.
5. **빈 상태(Empty State) 설계**: 첫 진입 시 보드가 비어 있으면 이탈한다. 샘플 공고 1건으로 데모 분석을 보여주는 온보딩 장치 필요.
6. **분석 결과의 면책과 근거 노출**: AI가 요건을 잘못 읽을 수 있다. "근거 문장 보기"와 참고용 고지가 없으면 오답 1회에 신뢰가 무너진다.

### 7.2 운영 갭 — 서비스를 굴리기 위한 뒷단

7. **LLM 비용 통제**: 분석 1회당 비용이 실존한다. 쿼터, 공고 스냅샷·구조화 결과 캐싱, 모델 티어링(구조화는 경량 모델, 매칭 리포트는 상위 모델)을 초기 설계에 포함해야 한다.
8. **분석 품질 모니터링 루프**: 사용자 👍/👎 피드백 → 어드민에서 오답 사례 검토 → 프롬프트/스키마 개선의 사이클이 없으면 품질이 정체된다. 프롬프트·모델 버전을 분석 결과에 기록해 회귀 비교가 가능해야 한다.
9. **크롤링 법무 리스크**: 채용 사이트 약관은 대부분 무단 수집을 금지한다. robots.txt 준수, 요청 제한, 스냅샷의 사적 이용 한정 + 장기적으로는 공식 API/제휴 전환 계획이 필요하다. **런칭 전 법무 검토 필수.**
10. **개인정보 보호**: 프로필은 민감한 개인정보 덩어리다. 암호화 저장, LLM 외부 전송 시 처리방침 고지, 회원 탈퇴 시 완전 삭제, (한국 기준) 개인정보처리방침·이용약관 정비가 선행되어야 한다.

### 7.3 성장 갭 — 검증과 확산 장치

11. **비로그인 체험 퍼널**: 가입 후에만 가치를 보여주면 전환이 어렵다. 공고 구조화까지는 비로그인 무료 → 적합도는 가입 후, 의 2단 퍼널을 MVP에 포함하는 것을 제안 (2.5 반영).
12. **결과 공유 카드**: "내 적합도 87점" 이미지 카드 공유(개인정보 제외)는 저비용 바이럴 장치다. Phase 2 후보.
13. **프로필 없는 첫 분석 허용 여부 (결정 필요)**: 프로필 입력 전 URL부터 넣는 사용자가 많을 것. "공고 요약까지 보여주고 → 적합도는 프로필 입력 후" 순서로 뒤집는 UX를 권장한다.
